DrDXT — validation complète de ton PC (pour aider le projet)

À quoi ça sert : DrDXT ne prétend qu'un réglage marche sur un matériel que si quelqu'un l'a vérifié dessus. Ce test
vérifie, sur TON PC, que chaque réglage de DrDXT se pose, se relit et se remet d'origine. Ton rapport sert de preuve
pour ton processeur et ta carte graphique (AMD surtout, c'est ce qui manque le plus).

Ce test MODIFIE des réglages de Windows, un par un, et remet chacun d'origine aussitôt :
mode Jeu, enregistrement en arrière-plan de la Game Bar, mode fenêtré optimisé, planification GPU accélérée,
accélération de la souris, plan d'alimentation, mode boost du processeur, limite de puissance de la carte graphique,
Anti-Lag, Vsync et plafond d'images FRTC (réglages du pilote AMD).
Il ne touche jamais au BIOS, ni à la tension, à la fréquence ou au ventilateur de la carte : le programme refuse
lui-même ces écritures. Il ne crée ni service ni point de restauration, et n'installe rien.

1. Ferme tous les jeux. Si un jeu s'ouvre pendant le test, le test s'arrête avant le réglage suivant.
2. Dézippe tout le dossier (clic droit sur le zip > Extraire tout), puis ouvre le dossier extrait.
3. Double-clique sur VALIDER.cmd.
   - Si Windows affiche « Windows a protégé votre ordinateur » : clique « Informations complémentaires »,
     puis « Exécuter quand même ». Le programme n'est pas signé (pas encore de certificat pour ce projet gratuit).
     Pour vérifier que le zip est bien celui du projet, compare son empreinte SHA-256 avec celle de la page
     de téléchargement (PowerShell : Get-FileHash DrDXT-Validation-....zip).
   - Windows demande « Voulez-vous autoriser cette application à apporter des modifications » pour DrDxt.Lanceur :
     clique « Oui ». Ce petit lanceur natif reçoit les droits administrateur et démarre le test dans un
     environnement propre.
4. Ne ferme pas la fenêtre noire. Compte une à deux minutes.
5. À la fin, un fichier DrDXT-validation-....txt est dans ton dossier Téléchargements. Sa première ligne dit
   « tout est remis d'origine », ou la liste de ce qu'il faut vérifier.
6. Envoie-le au projet : ouvre
   https://github.com/ablanchard-dev/drdxt/issues/new?template=rapport-de-verification.yml
   (il faut un compte GitHub gratuit), glisse le fichier dans le ticket, et écris si tu veux ce que tu as remarqué.

Ce qui est retiré du rapport avant qu'il soit écrit : le nom du PC et du compte Windows, ton dossier utilisateur,
les numéros de série (BIOS, carte mère, disques, mémoire), les adresses réseau (MAC et IP), les identifiants de compte
et de volume, les adresses de courriel. Il reste les modèles (processeur, carte, version du pilote) et les réglages
testés avec leurs valeurs. Relis-le avant de l'envoyer : tu vois exactement ce qui part.

Si la fenêtre se ferme toute seule ou si le PC plante pendant le test : relance VALIDER.cmd, ou REMETTRE.cmd. Le
programme remet d'abord d'origine ce qu'il avait laissé (il le note dans C:\ProgramData\DrDXT-banc, un dossier que
seuls les administrateurs peuvent modifier ; le fichier disparaît une fois tout remis).

Si la première ligne dit « À VÉRIFIER À LA MAIN » : le rapport donne, pour chaque réglage concerné, sa valeur
d'origine. Lance d'abord REMETTRE.cmd. Si la ligne reste là, remets ce réglage toi-même (logiciel AMD Adrenalin pour
Anti-Lag, le plafond d'images et la limite de puissance ; Paramètres de Windows pour le reste), puis envoie quand même
le rapport : c'est justement ce cas que le projet doit connaître.
